## 1. 需求 1：无边框

### 1.1 先把"边框"说清楚（三种解释，成本差 3 倍）

| 方案 | 用户看到的效果 | 改在哪里 | 能否运行时切换 | 成本 | 风险 |
| --- | --- | --- | --- | --- | --- |
| **A. 应用内边框**（推荐） | 阅读页隐藏顶部工具栏、底部进度条、目录分隔线、字号面板描边，正文铺到窗口边缘 | 仅渲染层（CSS 状态 + 组件条件渲染） | 可以，即时生效 | 0.5–1 人日 | 低 |
| **B. 窗口系统边框**（frameless） | 连 Windows 标题栏和最小化/关闭按钮都没了 | 主进程 `BrowserWindow` 构造参数 | **不行**，`frame` / `titleBarStyle` 只能在建窗时指定，切换需重建窗口或重启 | 1.5–2.5 人日 | 中高：拖拽区、边缘缩放、贴边分屏、双击最大化全要自己实现，做漏了窗口会"拖不动/关不掉" |
| **C. 两者都要** | A + B，最彻底 | 两处 | A 可切，B 需重启 | 2–3 人日 | 高 |

补充事实（Electron 官方文档）：

- `titleBarStyle: 'hidden'` + `titleBarOverlay: true` 可以保留 Windows/Linux 的原生最小化/最大化/关闭按钮，只需自绘标题栏并加 `app-region: drag` 拖拽区。
- 但这两个参数都是**构造参数**，运行中无法修改；想"设置里一开关就变"，只能重建窗口（要保存/恢复阅读位置、字号、目录开合状态）或提示"重启生效"。
- `win.setFullScreen(true)` 是唯一可以随时调用的"最接近无边框"的窗口级 API；Windows 全屏时系统标题栏与边框本身就不显示。

### 1.2 现状盘点：边框到底在哪

阅读页（`src/modules/reader/ReaderPage.module.css`）：

| 元素 | 边框 |
| --- | --- |
| `.toolbar` 顶部工具栏 | `border-bottom: 1px solid var(--border)` |
| `.footer` 底部进度条 | `border-top: 1px solid var(--border)` |
| `.toc` 目录抽屉 | `border-right` + `box-shadow` |
| `.fontGroup` / `.fontPanel` 字号区与面板 | `border` + `box-shadow` |
| `.page` | 背景铺满，无边框 |

主窗口（`electron/main/index.ts`）：默认系统边框，`autoHideMenuBar: true`，菜单已含 `togglefullscreen`（F11 可用）。

### 1.3 推荐方案：A + 全屏联动

理由：

1. 用户诉求是"**阅读时**隐藏边框"，A 正好只在阅读页生效，退出阅读页书架照常，符合直觉；
2. 零重启、零窗口重建，不会丢阅读位置；
3. 主要视觉收益（没有横线打断、正文铺满、工具条消失）A 已经 90% 拿到，剩下的"窗口标题栏"用全屏补上，且全屏是用户熟悉的操作；
4. B 的性价比太低：多花 1–1.5 人日，换来的是"窗口拖不动/关不掉/不能贴边"这类高危缺陷。

### 1.4 交互设计（供评审）

| 入口 | 行为 |
| --- | --- |
| 设置 → 阅读 → 「无边框阅读」 | 开关，默认关；只影响阅读页 |
| 设置 → 阅读 → 「工具栏自动隐藏」 | 子开关，默认开；关闭则工具栏常驻（无边框但仍可见） |
| `F11` / 菜单「视图 → 全屏」 | 全屏开关（已有能力，保留） |
| `Esc` | 若在全屏则退出全屏；否则无操作（不抢"返回书架"） |
| 鼠标移到窗口顶部 8px 内 | 工具栏以半透明浮层浮出，**不推挤正文**（`transform` 而非占位） |
| 移开 2s / 按 `Alt` | 浮层自动收起 |

细节约定：

- 沉浸模式下所有 1px 分隔线消失，面板（目录抽屉、字号面板）改为"阴影 + 背景模糊"分层，不再用描边；
- 正文上下留白略微加大（因为少了工具栏高度），章标题仍居中；
- 工具栏浮出时带 `backdrop-filter`，按钮保持可点击；
- 状态持久化到 `ReaderSettings`：新增 `immersiveReading: boolean`、`immersiveAutoReveal: boolean`（默认 `true`）；
- 不影响既有能力：字号快捷键、位置保持、进度落盘、目录跳转在沉浸模式下全部照旧。

### 1.6 验收标准（可测）

1. 开关关闭时，阅读页外观与 v0.1.1 **像素级一致**（截图对比）
2. 开启后：工具栏、底栏、目录右侧线、字号面板描边全部不可见；正文贴窗口边缘
3. 鼠标进入顶部 8px → 工具栏出现（≤100ms）；移开 2s 后消失
4. `F11` 全屏进入/退出后，阅读位置（字符偏移）与字号不变
5. 重启应用后开关状态与上次一致
6. 从阅读页返回书架，书架外观恢复正常（不残留沉浸样式）

### 1.7 风险与对策

| 风险 | 对策 |
| --- | --- |
| 浮出工具栏遮挡首行 | 用 `transform: translateY(-100%)` 悬浮，不占布局；浮出时给正文加 12px 顶距过渡 |
| 全屏后不知道怎么退出 | `Esc`、`F11`、浮出工具栏的返回键三入口都保留 |

| macOS 红绿灯按钮差异 | v0.2 只在 Windows 验收，macOS 列为已知限制 |
| 与主题切换叠加时层级错乱 | 沉浸态与主题共同走 CSS 变量，先定 z-index 分层表再写样式 |

## 2. 需求 2：我的建议

### 2.1 先看实测数据（用你那本 19MB / 3873 章的书）

| 场景 | 耗时 |
| --- | --- |
| 导入全书（解码 GB18030 + 归一化 + 切章 + 写 IndexedDB + 首屏渲染） | **782ms** |
| 首次展开目录（3873 项一次性渲染） | **439ms** |
| 目录展开状态下切到下一章 | **836ms** |
| 关闭目录后切到下一章 | **76ms** |

结论很清楚：**换章慢不是章节渲染慢，是 3873 项目录每次状态变化都全量重渲染**（11 倍差距）。而"沉浸阅读"必然要频繁开合目录 —— 所以目录虚拟化必须和无边框放进同一个版本，否则新功能会把旧问题放大成"打开目录就卡"。

### 2.2 建议纳入 v0.2 的清单

**P0 · 阅读体验包（v0.2.0）**

| # | 能力 | 说明 | 人日 |
| --- | --- | --- | --- |
| 1 | 无边框沉浸阅读 | 见第 1 节 | 1.6 |
| 2 | 目录虚拟化 + 行级 memo | 3873 项只渲染可视区约 20 项；目标换章 <100ms、开目录 <100ms | 1.0 |
| 3 | 主题：浅色 / 深色 / 护眼 / 跟随系统 | CSS 变量体系已就绪，主要是三套配色 + 深色下对比度校验 | 1.2 |
| 4 | 字体族切换 + 行距 / 页边距独立调节 | `ReaderSettings` 已有这三个字段，缺 UI 与生效链路 | 1.0 |
| 5 | 单书字号覆盖 | `fontSizeByBook` 早在 v0.1 预留，加"仅本书"开关即可 | 0.4 |
| | **小计** | | **5.2** |

**P1 · 检索与结构包（v0.2.1）**

| # | 能力 | 说明 | 人日 |
| --- | --- | --- | --- |
| 6 | 文内搜索 | 先在当前章内即时高亮，再 Worker 做全书索引搜索（10MB 需分片） | 2.5 |

| 8 | TOC 型 TXT 识别与去重 | 开头整页章节列表的书会被切出几百个空章，需识别"目录区"并跳过 | 1.5 |
| 9 | 拖拽导入 | `webUtils.getPathForFile` 经 preload 暴露 | 0.3 |

**P2 · 格式与排版（v0.2.2 及以后）**

| # | 能力 | 说明 | 人日 |
| --- | --- | --- | --- |
| 10 | EPUB 完整支持 | 需引入 zip/xml 解析依赖 + XHTML 渲染沙箱 + OPF/NCX 目录 | 4–6 |
| 11 | 横向分页 + 重排回位 | 离屏测量 + 防抖 + 防白屏，M4 当年特意推迟 | 3–4 |

### 2.3 关于先做 M5 打包（**已作废**，定案见第 0 节）

- 现在只能靠 `out/` + `electron.exe` 跑，**没有安装包就没有真实分发**，反馈只能靠你在本机试；
- electron-builder + NSIS 配置 + 图标 + 冷启动验收，约 1 人日，风险集中在首次下载打包资源；
- 打包还能顺带暴露"路径含中文/空格""asar 内文件读取"这类只在打包后出现的问题 —— 越晚做越贵。

### 2.4 版本节奏（已按定案调整）

```text
v0.2.0  P0 阅读体验包（含无边框）            ≈5.2 人日   ← 下一步
v0.2.1  P1 检索与结构包                      ≈5.3 人日
v0.2.2  P2 EPUB + 横向分页                   ≈7–10 人日
之后     M5 打包（NSIS 安装包）              ≈1.0 人日
```

### 2.5 不建议放进 v0.2 的东西

| 项 | 原因 |
| --- | --- |
| 单书主题/字体（跟字号一样按书存） | 状态组合爆炸，先用全局，看反馈再说 |
| 阅读时长统计 / 阅读报告 | 与"阅读器"核心体验无关，容易做成花架子 |
| 云同步 / 账号 | 与 v0.1 定案"不联网"冲突，属 v0.4 |
| 自定义识别规则编辑器 | 规则已是数据结构，但 UI 成本高，随 v0.3 书源一起做 |

## 5. v0.2.0 实施顺序（建议）

按"先治瓶颈、再上视觉"的顺序，每步都能独立验收：

| 顺序 | 任务 | 为什么排这个位置 |
| --- | --- | --- |
| 1 | 目录虚拟化 + memo | 836ms → 目标 <100ms；无边框会让目录开合更频繁，必须先解决 |
| 2 | 无边框沉浸阅读（含全屏联动） | 本次主需求，依赖 1 的性能基线 |
| 3 | 主题（浅/深/护眼/跟随系统） | 与沉浸态共用 CSS 变量与层级，一起做避免返工 |
| 4 | 字体族 + 行距/页边距 | 字段已在模型里，纯 UI 与生效链路 |
| 5 | 单书字号覆盖 | 依赖第 4 步的设置面板结构 |

验收口径：`node scripts/run.mjs verify` 全绿、E2E 新增用例通过、并用 19MB 真实书复测目录与换章耗时。
